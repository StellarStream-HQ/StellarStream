# Pull Request: Implement Withdraw Function, Exponential Vesting, and Dispute Resolution Framework

## Overview

This PR implements three core features for the StellarStream Contract-V1:

1. **Withdraw Function (#1439)** - Allows receivers to claim unlocked tokens from their active streams based on elapsed time
2. **Exponential Vesting Calculation (#1445)** - Implements quadratic (exponential) vesting for accelerated token unlocking
3. **Dispute Resolution Framework (#1471)** - Enables parties to raise disputes and have them resolved by arbitrators

---

## Changes Made

### 1. Withdraw Function (#1439)

**Files Modified:**
- `contracts/Contract-V1/src/lib.rs`
- `contracts/Contract-V1/src/errors.rs`
- `contracts/Contract-V1/src/test.rs`

**Implementation Details:**
- Enhanced the `withdraw` function with proper error codes:
  - `Error::NotReceiver` - when caller is not the stream's receiver (replaces generic `Unauthorized`)
  - `Error::InsufficientWithdrawable` - when nothing is withdrawable (replaces `InsufficientBalance`)
- Added **final withdrawal rounding dust handling**: when `current_time >= end_time`, the function transfers the exact remaining balance (`total_amount - withdrawn_amount`) to prevent contract insolvency from accumulated rounding errors
- Added **storage TTL extension** on every withdrawal to keep long-lived streams accessible
- Added **Withdrawal event emission** (`StreamClaimEvent`) with stream_id, claimer, amount, total_claimed, and timestamp
- Updated all existing tests to use the new error codes

### 2. Exponential Vesting Calculation (#1445)

**Files Modified:**
- `contracts/Contract-V1/src/math.rs`
- `contracts/Contract-V1/src/lib.rs`

**Implementation Details:**
- Added `calculate_unlocked_exponential` function that computes exponentially-vested amounts using the quadratic formula: `unlocked = total_amount * (elapsed² / duration²)`
- The function accepts a `paused_duration` parameter that subtracts paused time from elapsed time, ensuring paused periods never count toward vesting
- Uses **checked arithmetic** throughout to prevent overflow
- **Rounds down consistently** (floor division) to prevent contract insolvency
- Returns `0` before `start_time` and `total_amount` at/after `end_time`
- Updated the internal `calculate_unlocked` function in lib.rs to use the new exponential function with paused duration support
- Added **12 comprehensive tests** covering:
  - Before start time
  - After end time
  - Early stage (slow unlock)
  - Mid stage (25% at 50% time)
  - Late stage (fast unlock)
  - With paused duration
  - Large amounts
  - Overflow prevention
  - Comparison with linear vesting
  - Final unlock
  - Never exceeds total

### 3. Dispute Resolution Framework (#1471)

**Files Modified:**
- `contracts/Contract-V1/src/lib.rs`
- `contracts/Contract-V1/src/types.rs`
- `contracts/Contract-V1/src/errors.rs`
- `contracts/Contract-V1/src/storage.rs`
- `contracts/Contract-V1/src/dispute_test.rs`

**Implementation Details:**

**New Types (types.rs):**
- `DisputeResolution` enum with 4 resolution types:
  - `RefundSender(i128)` - Refund amount to sender
  - `PayReceiver(i128)` - Pay amount to receiver
  - `FreezeStream` - Freeze the stream
  - `CancelStream` - Cancel the stream entirely
- `Dispute` struct with dispute_id, stream_id, raised_by, reason, proposed_resolution, arbitrator_votes, resolved, raised_at, deadline, required_votes
- `DisputeRaisedEvent`, `DisputeVotedEvent`, `DisputeResolvedEvent` for event emission

**New Storage Keys (storage.rs):**
- `DISPUTE_COUNT` - Counter for dispute IDs
- `DISPUTE` - Prefix for dispute records
- `ARBITRATORS` - List of authorized arbitrators

**New Error Codes (errors.rs):**
- `DisputeNotFound` (29)
- `NotDisputeParty` (30)
- `NotArbitrator` (31)
- `DisputeAlreadyResolved` (32)
- `DisputeInProgress` (33)
- `AlreadyVoted` (34)
- `InsufficientVotes` (35)
- `DisputeExpired` (36)
- `InvalidResolution` (37)

**New Functions (lib.rs):**
- `add_arbitrator` - Add an address to the authorized arbitrator list (SuperAdmin only)
- `remove_arbitrator` - Remove an address from the arbitrator list (SuperAdmin only)
- `get_arbitrators` - Get the list of authorized arbitrators
- `is_arbitrator` - Check if an address is an authorized arbitrator
- `set_arbiter` - Set an arbiter for a specific stream (sender only)
- `freeze_stream` - Freeze a stream pending dispute resolution (arbiter only)
- `unfreeze_stream` - Unfreeze a stream after dispute resolution (arbiter only)
- `resolve_dispute` - Legacy dispute resolution by distributing remaining balance (arbiter only)
- `raise_dispute` - Raise a dispute on a stream (sender or receiver only)
- `vote_on_dispute` - Vote on a dispute (authorized arbitrators only)
- `get_dispute` - Fetch a dispute by ID
- `execute_dispute_resolution` - Internal helper to execute a dispute resolution once threshold is met

**Key Features:**
- Only sender or receiver can raise a dispute
- Only authorized arbitrators can vote
- Resolution auto-executes when vote threshold is reached
- Stream operations are blocked during active disputes (stream is frozen)
- All four resolution types are supported
- Arbitrator role is separate from Admin
- 7-day dispute deadline with expiration handling

**Tests Added (dispute_test.rs):**
- 20 comprehensive tests covering:
  - Add/remove arbitrator
  - Set arbiter
  - Freeze/unfreeze stream
  - Raise dispute by sender/receiver
  - Raise dispute by stranger fails
  - Raise dispute on unknown stream fails
  - Vote on dispute auto-executes
  - Vote by non-arbitrator fails
  - Vote on unknown dispute fails
  - Double vote fails
  - Resolve dispute (refund sender, pay receiver, freeze stream, cancel stream)
  - Legacy resolve dispute
  - Non-arbiter cannot freeze
  - Non-sender cannot set arbiter
  - Withdraw from frozen stream fails
  - Dispute expired
