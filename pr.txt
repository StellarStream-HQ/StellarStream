# Pull Request: Exponential (Quadratic) Vesting for Accelerated Token Unlocking

## Overview

This PR implements **exponential (quadratic) vesting** for accelerated token unlocking in the StellarStream Contract-V1 (Closes #1445). It adds a new `calculate_unlocked_exponential` function to the math module that computes the unlocked amount using quadratic acceleration, and routes the `CURVE_EXP` path in `unlocked_amount` (which backs `withdraw` and `cancel`) through it so it is pause-aware.

Exponential vesting unlocks slowly at first and accelerates over time:
- At 50% of the duration, only **25%** is unlocked.
- At ~70.7% of the duration, **~50%** is unlocked.
- At 100% of the duration, the **full amount** is unlocked.

---

## Summary

Unlock formula:

```
unlocked = total_amount * (elapsed^2 / duration^2)
```

where

```
elapsed   = current_time - start_time - paused_duration
duration  = end_time - start_time
```

**Key properties:**
- Returns `0` before `start_time`, and `total_amount` in full at/after `end_time`.
- Subtracts `paused_duration` from elapsed time, clamped at zero via `saturating_sub`, so time spent paused is excluded from vesting.
- Uses **checked arithmetic** throughout, so any intermediate overflow returns `0` instead of wrapping or panicking.
- Rounds down consistently (integer truncation), so the result is always `<= total_amount`.

## Implementation Details (math.rs)

`calculate_unlocked_exponential` implements:

**Formula:**
```
unlocked = total_amount * (elapsed^2 / duration^2)
elapsed  = current_time - start_time  (paused_duration subtracted, floored at 0)
duration = end_time - start_time
```

**Fast paths & guarantees:**
- **Before `start_time` / non-positive amount** -> returns `0` immediately.
- **At or after `end_time`** -> returns `total_amount` in full.
- **Zero duration** -> returns `total_amount` (fully unlocked).
- **Elapsed at or beyond duration** -> returns `total_amount` in full.
- **Checked arithmetic**: every multiply uses `checked_mul`, so any intermediate overflow returns `0` (never wraps or panics).
- **Bounded by `total_amount`**: since `elapsed <= duration` in the unlocked range, `elapsed^2 <= duration^2`, so the result is always `<= total_amount`.

**Pause handling:**
- Time spent paused is excluded from elapsed time, so a stream paused for N seconds behaves exactly like one that started N seconds later.
- `paused_duration` is subtracted from the raw elapsed time via `saturating_sub`; if it is at least as large as the raw elapsed time, the effective elapsed time is `0` and nothing has unlocked yet.

**Curve comparison with linear:**
- Exponential is below linear in the early/mid stages (slow start) and above it in the late stage (fast finish).
- At the exact midpoint linear grants 50% while quadratic grants only 25%.
- Both curves converge to the full amount at 100% of the duration.

## lib.rs Wiring

The `CURVE_EXP` branch previously computed the quadratic inline. This PR replaces it with a call to the new `calculate_unlocked_exponential`, passing `stream.paused_duration` so the exponential path is now **pause-aware** (`withdraw`, `cancel`, and `get_unlocked_amount` all benefit from accurate pause handling).
